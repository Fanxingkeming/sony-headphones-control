# LinkBuds S（WF-LS900N）能力清单

> 全部条目均在真机（MAC `AA:BB:CC:DD:EE:02`，固件 2.0.2）上跑过，
> 读写类都有「读回」验证，涉及 App 界面的另有截图对照。
> 协议细节见 `sony-protocol-reference.md` 第 12 节；工具 `tools/linkbuds.py`；
> 要给 C++ 客户端打补丁见 `linkbuds-client-patch.md`。

## 连接与握手

```
v2 服务 UUID 956C7B26-D49A-4BA8-B03F-B17D393CB6E2 + port 0（SDP 解析，0.1s 成功）
  → 00 00  INIT                 响应 8 字节 = v2
  → 02 00  GET_CAPABILITY_INFO  返回 MAC
  → 06 00  GET_SUPPORT_FUNCTION 少了这一步，后面的族全部不响应
```

设备**常忽略新会话的第一条 INIT**，要重试 3–5 次。同一时刻只接受一个 tandem 客户端，
手机 App 连着时 PC 会收到 `10050`。

> **2026-11-03 更正**：早先"必须写死通道 9"的结论作废。用 **v2 UUID** 走 SDP 0.1s
> 就解析成功（实测见 `tools/sdp_probe.py`）；连不上是因为原先用了 v1 UUID
> `96CC203E-…-E069BA`，LinkBuds S 不在此服务类别下注册。

## 逐项说明

### 电量（POWER 族）

```
22 00  ->  23 00 <pct> 00                 整体
22 01  ->  23 01 <左> 00 <右> 00          左右耳
22 02  ->  23 02 <pct> 00                 充电盒
```

TWS 特有：三段独立电量。

### 降噪（NCASM 族，type 0x17）

```
读  66 17  ->  67 17 <状态> <总开关> <NC模式> <环境声模式> <等级>
写  68 17 <状态> <总开关> <NC模式> <环境声模式> <等级>
```

| 字段 | 取值 |
|---|---|
| 状态 | `00` 渐变中、`01` 已完成（写入用 `01`） |
| 总开关 | `00` 关闭处理、`01` 开启处理 |
| NC 模式 | `00` 降噪、`01` 环境声 |
| 环境声模式 | `00` 普通、`01` 关注语音 |
| 等级 | 0–20 |

关注语音只在环境声下有效，且是**粘性**的（切降噪不会自动清）。

⚠️ `66 30` 不是降噪模式，它是 `NC_AMB_TOGGLE` 的「按键功能」，
改它等于改触摸分配。踩过这个坑，记在这里。

### 均衡器（EQEBB 族）

```
预设     读 56 00  ->  57 00 <preset> 06 <6 值>
         写 58 00 <preset> 00
自定义   写 58 00 A0 06 <6 值>        A0 = 自定义预设，值 = 增益 + 10
```

预设值：`00` 关闭、`10` 明亮、`11` 兴奋、`12` 柔和、`13` 放松、`14` 人声、
`15` 高音、`16` 低音、`17` 语音。写入自定义后预设自动变成 `A0`。

### DSEE Extreme（AUDIO 族 type 0x01）

```
读  E6 01  ->  e7 01 <0|1>       00 = 关闭，01 = 自动
写  E8 01 <0|1>
```

⚠️ v2 的 AUDIO type 比 v1 整体后移一位（v1 用 `0x02` 表示 DSEE），照 v1 发会写到连接模式上。

### 连接模式（AUDIO 族 type 0x00）

```
读  E6 00  ->  e7 00 <0|1>       00 = 音质优先，01 = 稳定优先
写  E8 00 <0|1>
```

切到稳定优先会让 LDAC 掉到 AAC，音频链路会重连。

### 智能对话 / Speak-to-Chat（SYSTEM 族 type 0x02）

```
读  F6 02  ->  f7 02 01 <val>        val: 00 = 开，01 = 关
写  F8 02 01 <val>
扩展 FA 02 ->  fb 02 <灵敏度> <关注语音> <退出时间>
```

设备**同时支持两套 inquired type**：`F6 02`（Type1）与 `F6 0C`（Type2）都有响应，
扩展参数 `FA 02` 回 5 字节（含关注语音）、`FA 0C` 回 4 字节。支持功能表里声明的是 Type2（`0xfc`）。

**⚠️ 开关方向是反的**：`OnOffSettingValue` 是 `00 = ON`、`01 = OFF`。
App 里显示「智能免摘：关闭」时读到的正是 `01`。
自测「写 01 读 01、写 00 读 00」看起来完全自洽，但语义全反——**必须用官方 App 定标**。

⚠️ 回显命令字是 `f9 0c`，不是 `f9 02`。按「第二字节等于请求第二字节」匹配会永远等不到。
⚠️ XM4(v1) 的智能免摘在 `F6 05`，两边不通。

### 自动断电（POWER 族 type 0x04）

```
读  26 04  ->  27 04 <当前> <上次>      实测 27 04 10 00
写  28 04 <值>
```

| 值 | 含义 | 是否接受 |
|---|---|---|
| `10` | 当耳机取下时关闭 | ✅ |
| `11` | 关闭 | ✅ |
| `00`/`01`/`02`/`03`/`04` | 5/30/60/180/15 分钟 | ❌ 全部被规整回 `10` |

和 App 界面只有两个选项一致。**别照抄别机型的定时档编码。**

### 按键 / 触摸分配（SYSTEM 族 type 0x03）

```
读  F6 03  ->  f7 03 02 <左> <右>
写  F8 03 02 <左> <右>
```

| 值 | 含义 | 单击 | 双击 | 点击三次 | 长按 |
|---|---|---|---|---|---|
| `35` | 环境声音控制 / Quick Access | 降噪/环境声 | 未分配 | 未分配 | 快速注意 |
| `20` | 播放控制 | 播放/暂停 | 下一首 | 上一首 | 语音助手 |
| `10` | 音量调节 | 音量 + | — | — | 音量 − |
| `FF` | 未分配 | — | — | — | — |

其它值一律被规整成 `FF`。

**写入前必须先发 `94 01 00`（开固定消息告警）**，否则设备静默忽略：
回显旧值、读回不变，和「不支持」完全一样。

某些组合（例如两耳都设成环境声控制 → 没有播放控制 → 禁用语音助手）会触发设备告警，
App 会弹「由于未分配播放控制，因此已禁用语音助手，是否更改？」，
此时需要回 `98 00 <MT> 01`（v2 第二字节是 `00`，v1 是 `01`）才真正生效。

**动作列表不可单独配置**：App 里「操作方法」的四行（单击/双击/点击三次/长按）
在控件树中 `clickable=false`，纯展示。内容完全由预设决定。
所以这台耳机上没有「自定义每个手势」这回事，只能选预设。

### 通知和语音向导（Table#2）

```
读  T2 48 01 00  ->  49 01 00        00 = 开
写  T2 48 01 <val>                   01 = 关
```

**注意方向是反的**：`00` = 开、`01` = 关（与 libmdr 的 `OnOffSettingValue{ON=0, OFF=1}` 一致）。
这是 v2 上唯一一条已知的 Table#2 命令，和 XM4(v1) 的 `48 01 01 <val>` 不同——**v2 是 3 字节，不带独立值字段**。

踩过的坑：一开始照 v1 发 4 字节 `48 01 01 00`，设备只回 `49 01 01`、忽略多余字节，
看起来"发出了但没生效"。App 抓包才看清是 3 字节。

### 智能对话扩展（SYSTEM 族 EXT_PARAM）

```
读  FA 02  ->  fb 02 <灵敏度> <关注语音> <退出时间>
写  FC 02 <灵敏度> <关注语音> <退出时间>
```

| 字段 | 取值 |
|---|---|
| 灵敏度 | `00` 自动、`01` 高、`02` 低 |
| 关注语音 | 实测 `01`，写 `00` 被拒（该字段本机不可改） |
| 退出时间 | `00` 快、`01` 中、`02` 慢 |

回显命令字是 `fd 0c ...`（不是 `fd 02`），和智能对话开关的 `f9 0c` 是同一类现象。

### 佩戴相关

```
F6 06  ->  f7 06 00 00 00 00 ff ff      佩戴检测状态（只读）
F6 01  ->  f7 01 00                     佩戴播放控制，写入被拒
```

### 多点连接（GENERAL 族 type 0xD2）

```
读  D6 D2  ->  d7 d2 00 <01=开 / 00=关>
写  D8 D2 00 <val>                       ❌ 设备一律回旧值
```

试过的全部无效：直接写、先查能力（`D0 D2 0C`）、先查状态（`D2 D2`）、
先开告警（`94 01 00` 后收不到 `99`）、用 v1 的 `settingType=01`。

**结论：多点连接在 v2 上只读。** 需要改开关时用手机 App。

注意 v2 与 v1 的 GENERAL 写法不同：

| | BOOLEAN | LIST |
|---|---|---|
| v1（XM4） | `01` | `02` |
| v2（LinkBuds S） | `00` | `01` |

搞错会全部无响应。值语义以实测为准：**`01` = 开**（libmdr 的枚举写成 ON=00，与实测相反）。

## 做不到的 / 没做的

| 项 | 状态 | 原因 |
|---|---|---|
| 多点连接写入 | ❌ 做不到 | 设备拒绝，六种前置组合全试过 |
| 自定义触摸动作 | ❌ 不存在 | 动作由预设决定，App 里那四行是只读展示 |
| 自适应声音控制 | ❌ 不是协议功能 | App 端做活动识别，只下发普通降噪命令 |
| 防漏音 / 省电模式 / 护理充电 | ❌ 无响应 | `E6 07`、`26 06`、`26 0C` 均无响应 |
| 振动 | ❌ 无响应 | `F6 00` 无响应 |
| 语音向导语言切换 | ⚠️ 未做 | 要上传语言包（几十 MB），写一半断掉有变砖风险，不建议碰 |

## 与 XM4（v1）的对照

| 项 | XM4 (v1) | LinkBuds S (v2) |
|---|---|---|
| INIT 响应 | 4 字节 | **8 字节** |
| 握手 | `00 00` → `02 00` | 多一步 **`06 00`** |
| 通道 | SDP 可解析 | **必须写死 9** |
| 电量 | `10 00` | `22 <type>`（三段） |
| 降噪 | `66 02` / `68 02`（8 字节） | `66 17` / `68 17`（5 字段） |
| 均衡 | `56 01` / `58 01` | `56 00` / `58 00` |
| DSEE | `E6 02` | `E6 01` |
| 智能免摘 | `F6 05` | `F6 02` |
| 触摸面板开关 | `D1`（GENERAL1） | 无（改为按键分配 `F6 03`） |
| 多点 | `D2`（可写，需告警） | `D2`（只读） |
| 告警应答 | `98 01 <MT> 01` | `98 00 <MT> 01` |
| GENERAL BOOLEAN | `01` | `00` |

两边**帧层完全一样**（`3E` / 转义 / 4 字节长度 / 校验 / seq-ACK），
`tandem_client.py` 可以直接复用，差异全在命令层与握手。

## 验证方法（这次实际用的）

1. **读回**：写完立刻 `GET` 同一参数，比较值是否变化。这是最可靠的一档。
2. **App 截图**：`adb shell input tap` 操作 + `screencap`，看 App 显示的取值。
3. **抓包 diff**：操作前后各拉一次 `btsnoop_hci.log`，按 `(cid, 方向)` 做字节差集，
   差出来的出站帧就是 App 的动作。定位未知功能只靠这个。
4. **控件树**：`uiautomator dump` 拿真实坐标和 `clickable` 属性，比按截图估坐标准
   （差 70 px 就会点空），也能判断某个界面元素到底能不能点。

一条经验：**遇到「回显旧值、读回不变」的写入，先补 `94 01 00` 开告警再判失败。**
这次按键分配、上次 XM4 多点，都是同一个原因造成的误判。
